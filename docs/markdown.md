# Разбор markdown

`tnt-markdown` разбирает разметку в дерево блоков, правит дерево
конвейером преобразований — якоря заголовкам, врезки, обёртка таблиц —
и рисует из него HTML. По тому же дереву читаются оглавление страницы
и её разделы для указателя поиска.

```lua
local markdown = require('tnt.markdown')

local page, meta = markdown.render('# Установка\n\nСначала — `make deps`.')
--> page = '<h1>Установка</h1>\n<p>Сначала — <code>make deps</code>.</p>'
```

Разбор ничего не бросает на плохом входе, экранирует всё, что уходит
в страницу, и отказывает только на входе больше предела.

## Зачем пакет

Раздел документации на сайте — это страницы, написанные markdown. Чтобы
показать их браузеру, разметку надо разобрать, и разобрать на узле:
класть в репозиторий готовый HTML значит держать два источника правды,
а собирать страницы снаружи — заводить ещё одну сборку ради текста.
Пакет делает для этого три вещи:

- **Отдаёт дерево, а не только страницу.** Оглавление, указатель поиска
  и правка перед показом читают то же дерево, из которого рисуется HTML:
  якорь в колонке справа обязан совпадать с якорем в странице, и двух
  правил имени у пакета нет.
- **Правит дерево конвейером.** Якоря, врезки и обёртка таблиц — шаги
  «дерево → дерево» списком, и приложение дописывает в список своё,
  не трогая готовую страницу строкой.
- **Не роняет показ.** Незакрытая ограда, битая таблица, чужой знак
  читаются как текст, а не срывают страницу целиком. Отказ один —
  на входе больше предела, — и он парой `nil, err`, а не съеденной
  памятью узла.

Написан он под документацию к пакетам — файлы, где заголовки, списки,
ограды кода и таблицы стоят разом, — и по ней же проверяется: каждый
документ каталога `docs/` разбирается проверками пакета и обязан дать
страницу с парными тегами, оглавление без повторов и по разделу на каждый
заголовок. Зависимость у пакета одна —
[`tnt-must`](https://github.com/tnt-skein/tnt-must), проверка аргументов;
ни часов, ни сети, ни `box` ему не нужно, поэтому нет ни внешних
зависимостей, ни состояния, ни `configure` с `new`: всё, что задаётся,
задаётся аргументом вызова.

## Как пользоваться

```lua
local markdown = require('tnt.markdown')

local page, meta = markdown.render('Шаги:\n\n- `make deps`\n- **make check**')

--> page = '<p>Шаги:</p>\n<ul>\n<li><code>make deps</code></li>'
-->     .. '\n<li><strong>make check</strong></li>\n</ul>'
--> meta = {}
```

У заголовка второго уровня и ниже появляется якорь — `id` и ссылка
на себя:

```lua
markdown.render('## Как пользоваться\n\nСначала — `make deps`.')

--> '<h2 id="как-пользоваться">Как пользоваться'
-->     .. '<a class="anchor" href="#как-пользоваться"'
-->     .. ' aria-label="Ссылка на этот раздел"></a></h2>'
-->     .. '\n<p>Сначала — <code>make deps</code>.</p>'
```

Разбор ничего не бросает на плохом входе: незакрытая ограда, таблица без
шапки, список без пробела после знака читаются как текст. Отказ у пакета
один, и он про размер:

```lua
local page, err = markdown.render(('x'):rep(100), { max_size = 64 })

--> page = nil
--> err.kind = 'too_large', err.size = 100, err.limit = 64
--> tostring(err) = 'разметка больше предела: 100 байт при пределе 64'
```

Род отказа — `markdown.TOO_LARGE`, размер и предел — байты. Строкой отказ
читается целиком: `tostring(err)`, склейка `'причина: ' .. err`
и `json.encode(err)` дают один и тот же текст.

Негодный аргумент — ошибка программиста, и вызов на нём бросает, виня
строку вызывающего: `markdown.render(42)` — «разметка — строка, а не
число».

| Вызов | Что отдаёт |
|---|---|
| `markdown.render(source[, options])` | `html, meta` либо `nil, err` |
| `markdown.parse(source[, options])` | дерево блоков и `meta` либо `nil, err` |
| `markdown.to_html(tree[, options])` | HTML из дерева — своего либо изменённого |
| `markdown.outline(source[, options])` | оглавление и `meta` либо `nil, err` |
| `markdown.sections(source[, options])` | разделы и `meta` либо `nil, err` |
| `markdown.outline_of(tree)` | оглавление по дереву |
| `markdown.sections_of(tree)` | разделы по дереву |
| `markdown.title_of(tree)` | заголовок страницы по дереву — текст первого блока-заголовка |
| `markdown.modifications()` | новый список преобразований пакета |
| `markdown.links(rewrite)` | шаг конвейера: адреса ссылок — правилом приложения |
| `markdown.walk(tree, visit)` | обход дерева для своего преобразования |
| `markdown.MAX_SIZE` | предел входа по умолчанию, 1 МиБ |
| `markdown.TABLE_CLASS` | класс обёртки таблицы, `table-scroll` |
| `markdown.TOO_LARGE` | род единственного отказа |

## Настройки

| Настройка | Умолчание | Что делает |
|---|---|---|
| `allow_html` | `false` | пускать ли сырой HTML из разметки в страницу |
| `max_size` | `1048576` | предел размера разметки, байт |
| `modify` | список пакета | список преобразований дерева по порядку |

Настройка с незнакомым ключом или негодным значением — ошибка
программиста, и бросок называет её по имени: `{ allow_htm = true }` даёт
«настройки: ключа «allow_htm» нет, есть allow_html, max_size, modify»,
а `{ max_size = 0 }` — «настройки.max_size — число больше 0, а не 0».

Сырой HTML по умолчанию экранируется и виден на странице текстом.
Умолчание названо вслух нарочно: правило «в страницу уходит только то,
что собрали мы» простое и проверяемое, а разметку пишут не всегда свои.
Предел размера — вторая половина того же правила: разбор строит дерево
в памяти, и документ, пришедший из чужих рук, иначе съел бы память узла.

Умолчание `modify` не пустое: без якорей, врезок и обёртки таблиц раздела
документации не собрать. Свой список отменяет умолчание целиком — порядок
шагов тоже решение вызывающего, — а `modify = {}` даёт голый разбор:

```lua
markdown.render('## Раздел', { modify = {} })   --> '<h2>Раздел</h2>'
```

## Что разбирается

| Разметка | Что выходит |
|---|---|
| `#` … `######` | `<h1>` … `<h6>` |
| абзац, строки подряд | `<p>`, перенос строкой |
| две пробела в конце строки, `\` в конце строки | `<br>` |
| `- `, `* `, `+ ` | `<ul><li>` |
| `1. `, `1) ` | `<ol><li>`, `start` — с номера первого пункта |
| ограда ``` ``` ``` и `~~~` с языком в шапке | `<pre><code class="language-lua">` |
| таблица чертами с `:---:` в разделителе | `<table>` со стилем выравнивания у ячеек |
| `> ` | `<blockquote>` |
| `---`, `***`, `___` | `<hr>` |
| `**жирный**`, `__жирный__` | `<strong>` |
| `*курсив*`, `_курсив_` | `<em>` |
| `` `код` `` | `<code>` |
| `[текст](адрес "подпись")` | `<a href title>` |
| `![что на ней](адрес)` | `<img src alt title>` |
| `<https://узел>`, `<duty@example.org>`, `https://узел` | `<a>` |
| `\*` и прочие экранированные знаки | сам знак |

Разметка внутри строки разбирается слева направо и никогда не
отказывает: знак, за которым не нашлось пары, остаётся собой. Серия
из одного знака — курсив, из двух — жирный; закрывает серию только серия
ровно такой же длины, поэтому `**жирный с *курсивом* внутри**`
разбирается вложенно, а `**` без пары остаётся текстом.

Подчёркивание не работает внутри слова: `request_id` и `имя_поля_таблицы`
остаются собой. Частью слова при этом считается буква любого языка —
иначе русское слово с подчёркиванием разъезжалось бы на курсив, — а вот
кавычка и тире словом не бывают, и «_курсив_» в ёлочках остаётся
курсивом. Знак разбирается целиком: у русской буквы «л» и у закрывающей
ёлочки последний байт один и тот же, и по байту их не различить.
У звёздочки правила про середину слова нет вовсе: ею выделяют и часть
слова.

Списки различают плотный и просторный: пустая строка внутри списка или
между пунктами делает его просторным, и тогда каждый пункт показывается
абзацем. Содержимое пункта начинается там, где начался его текст,
и продолжение пишется с тем же отступом.

## Конвейер преобразований

Страница документации получается не одним разбором. Заголовку нужен якорь,
цитате с маркером — вид врезки, таблице — обёртка, которая прокручивается
на узком экране, а заголовок страницы из содержимого убирается, потому что
его рисует шапка. Каждое такое дело — шаг «дерево → дерево», и порядок
шагов задаёт список.

| Шаг | Что делает |
|---|---|
| `markdown.anchors` | `id` и ссылка на себя у заголовков h2–h4 |
| `markdown.callouts` | цитата с маркером становится врезкой со своим видом |
| `markdown.table_scroll` | таблица уезжает в обёртку `div.table-scroll` |
| `markdown.without_first_heading` | первый блок-заголовок со страницы прочь |
| `markdown.links(rewrite)` | адрес каждой ссылки — через правило приложения |

Первые три идут по умолчанию, остальные добавляют сами. Четвёртый убирает
содержимое, и молчаливым умолчанием такое не делается; пятый собирается
из правила приложения, и без правила его нет (см. «Перевод ссылок»).
Убирающий заголовок ставят первым шагом — тогда убранный заголовок
не успевает занять якорь:

```lua
local pipeline = markdown.modifications()

table.insert(pipeline, 1, markdown.without_first_heading)

markdown.render('# Установка\n\n## Шаги\n\nдальше', { modify = pipeline })

--> '<h2 id="шаги">Шаги<a class="anchor" href="#шаги"'
-->     .. ' aria-label="Ссылка на этот раздел"></a></h2>\n<p>дальше</p>'
```

Своё преобразование — такая же функция: принимает дерево, отдаёт дерево.
Обойти его вглубь помогает `markdown.walk`; шаг, вернувший `nil` вместо
узла, убирает узел со страницы:

```lua
local function without_rules(blocks)
    return markdown.walk(blocks, function(node)
        if node.kind == 'rule' then
            return nil
        end

        return node
    end)
end

markdown.render('раз\n\n---\n\nдва', { modify = { without_rules } })

--> '<p>раз</p>\n<p>два</p>'
```

Шаг, вернувший не дерево, называется вслух и на месте: `markdown.render`
бросает «дерево от преобразования 2 — массив, а не nil», а не роняет
разбор внутри следующего шага.

Вглубь обход идёт **до** самого шага: узел, который шаг только что завёл,
не обходится. Иначе обёртка таблицы снова встретила бы в себе таблицу
и оборачивалась бы, пока не кончится стек.

### Якоря

Якорь считается из текста заголовка, и кириллица в нём остаётся
кириллицей: «Как пользоваться» → `как-пользоваться`. Правил три: буквы
в строчные, всё, что не буква и не цифра, — разделитель (подряд идущие
дают один дефис), повтор внутри страницы получает числовой хвост.

Хвост считается до свободного имени, а не просто «второй по счёту»:
страница, где есть и «Раздел», и «Раздел 2», иначе получила бы два якоря
`раздел-2`, и ссылка на второй уводила бы к третьему. Заголовок без букв
и цифр — «—» или один значок — становится `section`: ссылаться на раздел
можно всегда.

Ссылка на себя пуста, и класс у неё `anchor`: знак решётки, значок или
показ по наведению мыши рисует приложение стилем. Подпись для чтеца
у ссылки есть — без неё пустая ссылка читалась бы как «ссылка» и ничего
больше.

### Врезки

Врезка — она же плашка — это цитата, начатая маркером. Маркер пишется
двояко: жирным словом в начале цитаты или скобочной меткой. Вид уходит
классом, а цвет, значок и заголовок врезки рисует приложение.

Класс собирается из вида: `callout callout-note`, `callout callout-warning`,
`callout callout-tip`.

| Маркер | Вид |
|---|---|
| `**Примечание.**`, `**Важно.**`, `[!NOTE]`, `[!IMPORTANT]` | `note` |
| `**Осторожно.**`, `**Внимание.**`, `[!WARNING]`, `[!CAUTION]` | `warning` |
| `**Совет.**`, `[!TIP]` | `tip` |

Маркер читается без учёта регистра и точки на конце, а из содержимого
убирается: подпись «Примечание» рисует приложение по классу — тогда она
одинакова у всех врезок страницы, а не берётся из того, как её написал
автор.

```lua
markdown.render('> [!WARNING]\n> POST не повторяется никогда.')

--> '<aside class="callout callout-warning">'
-->     .. '\n<p>POST не повторяется никогда.</p>\n</aside>'

markdown.render('> **Совет.** Берите `make quick`.')

--> '<aside class="callout callout-tip">'
-->     .. '\n<p>Берите <code>make quick</code>.</p>\n</aside>'
```

Цитата без маркера остаётся цитатой, и цитата, начатая списком или
оградой кода, — тоже: врезкой становится только то, что названо врезкой
явно.

### Обёртка таблиц

Таблица уезжает в `div` с классом `table-scroll` (он же
`markdown.TABLE_CLASS`). Прокрутку задаёт приложение стилем — пакет
называет место, где она нужна:

```lua
markdown.render('| Пакет |\n|---|\n| `tnt-must` |')

--> '<div class="table-scroll">\n<table>\n<thead>\n<tr>\n<th>Пакет</th>'
-->     .. '\n</tr>\n</thead>\n<tbody>\n<tr>\n<td><code>tnt-must</code></td>'
-->     .. '\n</tr>\n</tbody>\n</table>\n</div>'
```

Обёртка — общий узел `wrap` с полем `class`: в неё оборачивают что угодно
своё, не заводя нового рода узла, которого рисовальщик не знает.

### Перевод ссылок

Ссылка `[маршруты](router.md#параметры)` написана для того, кто читает
документы файлами, а на сайте ей место на странице раздела. Адреса сайта
знает только приложение, и правило перевода пишет оно. Пакет знает
другое — где в дереве лежат ссылки: в абзацах и заголовках, в ячейках
таблиц, внутри выделения, — находит их сам и отдаёт правилу адрес
каждой. Иначе приложению пришлось бы повторять у себя форму дерева,
и первая же ссылка в ячейке таблицы осталась бы ссылкой на файл.

```lua
local pipeline = markdown.modifications()

table.insert(pipeline, markdown.links(function(href)
    local name, rest = href:match('^([%w_-]+)%.md(.*)$')

    if name ~= nil and (rest == '' or rest:sub(1, 1) == '#') then
        return '/docs/' .. name .. rest
    end
end))

markdown.render('См. [маршруты](router.md#параметры) и [узел](https://tarantool.io).', { modify = pipeline })

--> '<p>См. <a href="/docs/router#параметры">маршруты</a>'
-->     .. ' и <a href="https://tarantool.io">узел</a>.</p>'
```

Правило отдаёт новый адрес строкой, а `nil` оставляет прежний: чужой
адрес правило пропускает, ничего для него не написав. Картинка — не
ссылка, и её адрес правилу не приходит. Новый адрес проходит тот же
запрет схем и ту же чистку невидимых знаков, что и написанный
в разметке: правило, собравшее адрес из входа, иначе протащило бы
`javascript:` мимо разбора.

Правило, вернувшее не строку, называется вслух и целиком — «адрес
от перевода ссылок — строка, а не число», — а не функция на месте
правила — ошибка того, кто собрал шаг: `markdown.links('/docs')` бросает
«перевод ссылок — функция или вызываемая таблица, а не строка» и винит
строку вызывающего.

## Оглавление и разделы

Оглавление и разделы читаются из того же дерева, из которого рисуется
страница, и якорь берут из него же — тот, что поставил конвейер. Второго
правила имени у пакета нет: разойдясь с первым на одном заголовке, колонка
оглавления уводила бы в пустоту, и заметно это стало бы только по жалобе
читателя.

**Оглавление** — заголовки h2–h4 подряд, с уровнем, текстом и якорем;
вложенность колонка выводит из уровня сама:

```lua
markdown.outline('# Пакеты\n\n## Кэш\n\n### Драйверы\n\n## Кэш')

--> { { level = 2, text = 'Кэш', anchor = 'кэш' },
-->   { level = 3, text = 'Драйверы', anchor = 'драйверы' },
-->   { level = 2, text = 'Кэш', anchor = 'кэш-2' } }
```

**Раздел** — заголовок и текст под ним до следующего заголовка, какого бы
уровня тот ни был. Текст подраздела в родителя поэтому не входит:
найденное слово обязано вести к тому якорю, где оно и написано, а не
к началу большого раздела, где его придётся искать глазами.

```lua
markdown.sections('## Кэш\n\nДрайвер `space`.\n\n### Драйверы\n\nИх два.')

--> { { level = 2, title = 'Кэш', anchor = 'кэш', text = 'Драйвер space.' },
-->   { level = 3, title = 'Драйверы', anchor = 'драйверы', text = 'Их два.' } }
```

Текст раздела голый: без разметки и без тегов, зато с содержимым ограды
кода и ячеек таблицы — по документации ищут и имя функции, и строку
настройки, а они стоят как раз в примерах и таблицах. Блоки разделены
переводом строки, перенос внутри абзаца — пробелом: слова по обе стороны
переноса иначе слиплись бы в одно.

Заголовки первого уровня и ниже четвёртого в оглавление не идут, и раздела
не заводят: первый — заголовок страницы, у него своё место в шапке, а
подпись внутри раздела в колонке справа только мешает. Текст до первого
заголовка второго уровня поэтому ни одному разделу не принадлежит — это
вступление страницы, и показывает его приложение.

Оглавление и разделы читаются и по дереву, которое правили руками:
`markdown.outline_of(tree)` и `markdown.sections_of(tree)`.

**Заголовок страницы** — `markdown.title_of(tree)`: голый текст первого
блока, если это заголовок, иначе `nil`. Это тот самый заголовок, который
убирает шаг `markdown.without_first_heading`: шапка страницы рисует его
сама, и текст ей берут отсюда. Правило у обоих одно — первый блок,
уровень не важен, — иначе шапка показала бы одно, а из страницы пропало
бы другое. Читают заголовок шагом, который его и убирает, и ставят этот
шаг первым:

```lua
local title
local pipeline = markdown.modifications()

table.insert(pipeline, 1, function(blocks)
    title = markdown.title_of(blocks)

    return markdown.without_first_heading(blocks)
end)

local page = markdown.render('# Разбор `markdown`\n\nтекст', { modify = pipeline })

--> title = 'Разбор markdown'
--> page = '<p>текст</p>'
```

## Ссылки остаются ссылками

Адрес не трогается: `[установка](install.md#шаги)` так и уходит
в `href`. Во что превратить ссылку на соседний документ, знает
приложение — оно одно и знает свои адреса, — а не разбор разметки.
Своё правило приложение ставит шагом конвейера `markdown.links`
(см. «Перевод ссылок»).

Схема, исполняющая код в браузере, в ссылку не пускается: у
`[клик](javascript:alert(1))` адрес пустеет, а текст ссылки остаётся
виден. Ищется схема в адресе без невидимых знаков, и они же из адреса
убираются: браузер выбрасывает их сам, и `java`, перенесённое на строку
выше от `script:`, иначе прошло бы мимо запрета, а в браузере собралось
бы в рабочую схему. Перенос попадает в адрес легко — строки абзаца
склеены им же.

Ссылки внутри ссылки не бывает: в `[https://узел](https://узел)` текст
остаётся текстом, иначе браузер получил бы `<a>` внутри `<a>`. Голый
адрес в тексте кончается там, где кончается сам адрес: хвост
предложения — точка, скобка, закрывающая ёлочка — в него не входит.
А «`http://`» без хозяина ссылкой не становится вовсе: это пример
записи, а не адрес.

## Шапка документа

Страница знает о себе больше, чем видно в тексте: заголовок для
оглавления, порядок в разделе, дата. Такие сведения пишутся шапкой
в начале файла и в страницу не попадают:

```lua
local page, meta = markdown.render('---\ntitle: Установка\nweight: 10\n---\n# Установка')

--> page = '<h1>Установка</h1>'
--> meta = { title = 'Установка', weight = '10' }
```

Значения остаются строками: что значит `weight: 10` для страницы, знает
приложение. Шапкой считается только то, что разбирается целиком: первая
строка — черта, ниже есть вторая, а между ними одни пары и пустые
строки. Иначе черта остаётся разделителем, каким её и писали, —
документ, начатый с `---` и заголовка, не должен терять начало.

## Дерево блоков

`parse` отдаёт то же дерево, из которого рисуется страница. По нему
строят оглавление и указатель поиска, его же правят перед показом
и рисуют потом через `to_html`:

```lua
local tree = markdown.parse('# Заголовок\n\nабзац')

tree[1].level = 2

markdown.to_html(tree)   --> '<h2>Заголовок</h2>\n<p>абзац</p>'
```

Приходит оно уже с преобразованиями — якорь у заголовка, врезка вместо
цитаты, обёртка вокруг таблицы:

```lua
markdown.parse('## Раздел\n\n> [!NOTE]\n> Врезка.')

--> { { kind = 'heading', level = 2, anchor = 'раздел',
-->     inline = { { kind = 'text', text = 'Раздел' } } },
-->   { kind = 'callout', view = 'note', blocks = { { kind = 'paragraph',
-->     inline = { { kind = 'text', text = 'Врезка.' } } } } } }
```

Второй раз конвейер не идёт: `to_html` рисует дерево как есть, иначе якоря
встали бы заново, а обёртка обернулась дважды. Дерево — массив блоков,
и на другом `to_html` бросает: `markdown.to_html('страница')` — «дерево
блоков — массив, а не строка».

Род узла лежит в поле `kind`.

| Род блока | Поля |
|---|---|
| `heading` | `level`, `inline`, `anchor` — его ставит конвейер |
| `paragraph` | `inline` |
| `code` | `language`, `text` |
| `list` | `ordered`, `start`, `tight`, `items` — у каждого `blocks` |
| `quote` | `blocks` |
| `callout` | `view` (`note`, `warning`, `tip`), `blocks` |
| `wrap` | `class`, `blocks` |
| `table` | `align`, `head`, `rows` — ячейка это список вкраплений |
| `rule` | — |
| `html` | `text` |

| Род вкрапления | Поля |
|---|---|
| `text`, `code`, `html` | `text` |
| `strong`, `emphasis` | `inline` |
| `link` | `href`, `title`, `inline` |
| `image` | `src`, `title`, `inline` — из него берётся `alt` |
| `break`, `softbreak` | — |

Узел незнакомого рода — ошибка того, кто собрал дерево руками: `to_html`
бросает «блок разметки «сноска» пакету незнаком», а не рисует пустоту.
Своя разметка для приложения — это `wrap` со своим классом либо узел
`html` с готовой строкой, а не новый род.

## Экранирование

Экранируется всё, что уходит в страницу: текст абзаца, содержимое
ограды, адрес ссылки и подпись. Знаков пять — `& < > " '`, — и больше
не надо: экранировать остальное значило бы портить кириллицу
и пунктуацию сущностями без нужды.

Не экранируется только то, что пакет собрал сам: теги и класс языка,
у которого имя экранировано. Поэтому `<имя>` в тексте остаётся `<имя>`
на экране, а `<script>` из чужой разметки не станет тегом.

## Чем пришлось поступиться

- **Кода отступом в четыре пробела нет.** В документации, под которую
  пакет написан, код пишется оградами, а продолжение пункта списка
  с отступом иначе молча превращалось бы в код. Отступ перед блоком
  поэтому ни на что не влияет.
- **Заголовков, подчёркнутых снизу, нет.** Строка `---` всегда
  разделитель: ею разделены разделы доброй половины документов, и
  заголовок из неё превращал бы последний абзац раздела в заголовок.
- **Серии выделения длиннее двух знаков — просто знаки.** `***x***`
  остаётся собой. В документации тройная звёздочка не встречается,
  а разбор её стоил бы отдельного правила деления серий.
- **Ссылок по метке нет.** `[текст][метка]` с объявлением `[метка]: адрес`
  ниже остаётся текстом: вторая таблица меток — это ещё один проход
  по документу и ещё один вид висящей ссылки.
- **Сущности во входе не разбираются.** `&amp;` в разметке — это текст
  из пяти знаков, и на странице он показывается как есть. Иначе
  экранирование пришлось бы делать разным для разных мест.
- **Ленивого продолжения нет.** Строка без отступа кончает пункт списка,
  строка без `>` кончает цитату. Так разбор не гадает, чьё это
  содержимое; в документации такой записи и нет.
- **Таблица требует черты и в шапке, и в разделителе**, а строка таблицы
  кончается пустой строкой или строкой без черты. Строгость тут дешевле
  разбирательств: «таблица без шапки» не должна съедать следующий абзац.
- **Адрес не кодируется.** Пробел в адресе так и уйдёт пробелом:
  кодировать чужой адрес значит однажды закодировать его дважды.
- **Шапка документа — не YAML.** Только пары «ключ: значение», значения
  строками, без списков и вложенности. Разбор YAML — отдельная забота,
  и Tarantool умеет его сам.
- **Пустые теги пишутся по HTML5**: `<br>` и `<hr>`, без косой черты.
- **Подпись картинки — голый текст.** Разметка внутри `![…]` в `alt`
  не попадает: атрибут не показывает тегов.
- **Якорь остаётся кириллическим.** «Как пользоваться» даёт
  `как-пользоваться`, а не транслитерацию: ссылки внутри документов
  пишутся по-русски (`markdown.md#врезки`), и транслитерация разошлась бы
  с ними. К тому же она необратима — `ё` и `йо` дают одно и то же имя,
  и два разных раздела получили бы один якорь. В `id` по HTML годится
  любой знак, кроме пробельного, а хвост адреса с русскими буквами
  браузер кодирует сам.
- **Якорь получают h2–h4, и только верхним уровнем.** Заголовок страницы
  рисует шапка, подпись ниже четвёртого уровня в колонке справа только
  мешает, а заголовок внутри цитаты или пункта списка — часть примера:
  раздел страницы бывает только верхним уровнем.
- **Маркер врезки из содержимого убирается.** Подпись «Примечание» рисует
  приложение по классу — тогда она одинакова у всех врезок страницы
  и переводится вместе с оформлением, а не берётся из того, как её
  написал автор. Без стилей врезка выглядит обычным текстом, и это лучше,
  чем `[!NOTE]` посреди страницы.
- **Первый заголовок убирается только первым блоком.** Страница, начатая
  абзацем, ничего не теряет: «первый заголовок где-то посреди текста»
  значил бы, что содержимое пропадает неизвестно откуда.
- **Вглубь обход идёт до шага, а не после.** Узел, который шаг только что
  завёл, не обходится, и преобразование не может пройти по своему же
  выводу. Иначе обёртка таблицы снова встретила бы в себе таблицу
  и оборачивалась бы, пока не кончится стек.
- **Вложенность кончается на 32 уровнях.** Цитата в цитате и список
  в списке разбираются вызовом того же разбора, и глубина вложенности —
  это глубина стека: документ из десятков тысяч знаков `>` подряд ронял
  бы разбор переполнением. За пределом строки читаются текстом.
  В документации вглубь идут на три-четыре уровня.

## Чего пакет не делает

- Не знает HTTP и кэша: страницу отдаёт роутер, а помнит её приложение.
  Разбор — чистая работа со строкой, и место его ответа решает вызывающий.
  Разметку в готовую страницу сайта одевают шаблоны приложения.
- Не оформляет того, что называет: цвет врезки, знак у ссылки на раздел,
  прокрутка обёртки, колонка оглавления справа — стили и шаблоны
  приложения. Пакет отдаёт вид классом и место — обёрткой.
- Не трогает готовый HTML строкой: преобразования правят дерево. Правка
  страницы образцом не знает ни вложенности, ни того, что уже
  экранировано.
- Не знает адресов сайта: во что превратить ссылку на соседний документ,
  решает правило приложения, а пакет только находит ссылки в дереве
  и отдаёт их правилу (`markdown.links`).
- Не подсвечивает код. Язык уходит классом `language-<имя>`, и дальше
  дело браузера: пакету незачем знать ни одного языка.

## Проверки

Проверки лежат в `test/`, по файлу на модуль, и идут на luatest:
`.rocks/bin/luatest test/`. Страница, дерево, оглавление и разделы
сверяются целиком и дословно — вплоть до перевода строки между тегами.
Живая проверка `docs_test.lua` разбирает каждый документ каталога `docs/`
и требует от него страницу с парными тегами, оглавление без повторов
и по разделу на каждый заголовок.

Покрытие строк — 100 %, убитых мутантов — 100 % (277 проверок, 1127 мутантов
в восемнадцати модулях).
