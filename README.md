# tnt-markdown

Разбор markdown для Tarantool: разметка разбирается в дерево блоков,
дерево правит конвейер преобразований — якоря заголовкам, врезки,
обёртка таблиц, — а из него рисуется HTML. По тому же дереву читаются
оглавление страницы и её разделы для указателя поиска.

```lua
local markdown = require('tnt.markdown')

local page, meta = markdown.render('## Установка\n\nСначала — `make deps`.')

--> '<h2 id="установка">Установка<a class="anchor" href="#установка"'
-->     .. ' aria-label="Ссылка на этот раздел"></a></h2>'
-->     .. '\n<p>Сначала — <code>make deps</code>.</p>'

markdown.outline('## Кэш\n\n### Драйверы')
--> { { level = 2, text = 'Кэш', anchor = 'кэш' },
-->   { level = 3, text = 'Драйверы', anchor = 'драйверы' } }
```

Зависимость одна — [tnt-must](https://github.com/tnt-skein/tnt-must),
проверка аргументов.

## Зачем

Раздел документации на сайте — это страницы, написанные markdown, и
разбирать их надо на узле: готовый HTML в репозитории — второй источник
правды, сборка снаружи — ещё одна сборка ради текста. Пакет делает
для этого четыре вещи:

- **Отдаёт дерево, а не только страницу.** Оглавление, указатель поиска
  и правка перед показом читают то же дерево, из которого рисуется HTML:
  якорь в колонке справа совпадает с якорем в странице.
- **Правит дерево конвейером.** Якоря, врезки и обёртка таблиц — шаги
  «дерево → дерево» списком; приложение дописывает в список своё.
- **Не роняет показ.** Незакрытая ограда, битая таблица, чужой знак
  читаются как текст. Отказ один — вход больше предела — и он парой
  `nil, err`, а не съеденной памятью узла.
- **Экранирует всё.** Текст, код, адрес и подпись уходят в страницу
  сущностями; сырой HTML во входе по умолчанию тоже.

## Установка

```sh
tt rocks install tnt-markdown --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-markdown.git
cd tnt-markdown && tt rocks make
```

## Как пользоваться

| Вызов | Что отдаёт |
|---|---|
| `markdown.render(source[, options])` | `html, meta` либо `nil, err` |
| `markdown.parse(source[, options])` | дерево блоков и `meta` либо `nil, err` |
| `markdown.to_html(tree[, options])` | HTML из дерева — своего либо изменённого |
| `markdown.outline(source[, options])` | оглавление — заголовки h2–h4 с якорями |
| `markdown.sections(source[, options])` | разделы — заголовок, якорь и текст без разметки |
| `markdown.outline_of(tree)`, `markdown.sections_of(tree)` | то же по готовому дереву |
| `markdown.title_of(tree)` | заголовок страницы — текст первого блока-заголовка |
| `markdown.modifications()` | новый список преобразований пакета |
| `markdown.links(rewrite)` | шаг конвейера: адреса ссылок — правилом приложения |
| `markdown.walk(tree, visit)` | обход дерева для своего преобразования |

Настройки: `allow_html` (по умолчанию `false`), `max_size` (по умолчанию
1 МиБ, `markdown.MAX_SIZE`) и `modify` — список преобразований дерева.

### Что разбирается

Заголовки `#`–`######`, абзацы и переносы, списки с вложенностью
(плотные и просторные), ограды кода с языком в шапке, таблицы чертами
с выравниванием, цитаты, разделители; внутри строки — `**жирный**`,
`*курсив*`, `` `код` ``, ссылки с подписью, картинки, автоссылки и голые
адреса. Шапка документа `---` … `---` уходит в `meta` парами строк.

### Конвейер

По умолчанию идут три шага: `markdown.anchors` (якорь и ссылка на себя
у h2–h4), `markdown.callouts` (цитата с маркером `> [!WARNING]` или
`> **Совет.**` становится `<aside class="callout callout-tip">`)
и `markdown.table_scroll` (таблица в `div.table-scroll`). Четвёртый —
`markdown.without_first_heading` — добавляют сами:

```lua
local pipeline = markdown.modifications()

table.insert(pipeline, 1, markdown.without_first_heading)

markdown.render(source, { modify = pipeline })
```

Своё преобразование — функция «дерево → дерево»; шаг, вернувший `nil`
из `markdown.walk` вместо узла, убирает узел со страницы. `modify = {}`
даёт голый разбор.

Ссылки на соседние документы переводит в адреса сайта правило
приложения, а находит их в дереве пакет — в абзацах, заголовках,
ячейках таблиц и внутри выделения:

```lua
table.insert(pipeline, markdown.links(function(href)
    local name, rest = href:match('^([%w_-]+)%.md(.*)$')

    if name ~= nil and (rest == '' or rest:sub(1, 1) == '#') then
        return '/docs/' .. name .. rest   -- router.md#шаги → /docs/router#шаги
    end
end))
```

`nil` оставляет адрес прежним, а новый проходит тот же запрет схем,
что и написанный в разметке. Текст убранного заголовка для шапки
страницы даёт `markdown.title_of(tree)`.

### Отказ

```lua
local page, err = markdown.render(source, { max_size = 64 * 1024 })

if page == nil and err.kind == markdown.TOO_LARGE then
    -- разметка больше предела: err.size и err.limit — байты
end
```

Негодный аргумент — ошибка программиста: `markdown.render(42)` бросает
«разметка — строка, а не число» и винит строку вызывающего.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (277 проверок, 1127 мутантов
в восемнадцати модулях). Страница, дерево, оглавление и разделы сверяются
дословно; живая проверка разбирает каждый документ каталога `docs/`
и требует парных тегов, оглавления без повторов и раздела на каждый
заголовок.
